# 検証記録の区分

本アプリはv0.1.2候補です。以下のv0.1.0からの検証記録を保持し、パス短縮と確認済みマーカーの差分を別に確認しています。自動試験、SDK保存・再読込み、GPU OCR、Viewer手操作、現地実務図面、別PCを別の項目として記録します。

## 実施済みの基礎検証

- 基準v0.1.5ソースZIPは338,622 bytes、SHA-256 `6d37559afc0fee01f7460a0d8d1cf67ed2ff2628422d2af97a18073ce22b468c`。CRCと全90ファイルのSHA一致を確認。
- 同封Core 1.0.1 wheelのSHA-256は`7ea3a6d1623238180ccb400237a753b616dccf72761ba83d97fee1b55f7f5f58`。CoreのMIT・RECORD・内容検査を通過。
- 新しい切り出しAPIで、公開Cadsy試料2枚・8項目の原文一致を実GPU確認。英語の短い文字列で、正規化なし。日本語・実務図面の精度結果ではない。
- 新しいXDW APIで、人工A4背景生成、赤枠配置、矩形別分割、保存後再読込み、原画像と編集XDWの保持をDocuWorks 10.1.1で確認。

## 新アプリの自動・実機試験

2026年10月14日、Windows x64、DocuWorks 10.1.1、Core 1.0.1、RTX 3060 12GBで確認しました。

| 試験 | 結果 | 区分 |
|---|---|---|
| 新アプリCPU試験 | 91件成功 | 新構築runtimeでも実行。過去版の件数は含まない |
| 新環境の初期設定BAT | 終了コード0、実OCR・SDK矩形読戻し成功 | 検証済み取得cache98件を再利用し、runtimeは新規構築 |
| 通常の抽出BAT | PDF4ページ＋XDW4ページ、48項目が期待値と完全一致 | 自作人工図面。実務精度の測定ではない |
| 回転と表示位置 | 0／90／180／270度を含む8ページ | 表示はすべてA4縦、別途四隅の基準位置を検査 |
| 文字と空欄 | 番号、長いTitle、2行、日本語、式文字列、空欄 | 40項目取得、空欄8項目は未検出。先頭ゼロを保持、Excel数式ノード0 |
| テンプレート作成BAT | 全文OCR14領域、白紙PNG警告0、XDW生成成功 | 自作の独立見本 |

Excel出力失敗後も完成OCRを保持して再出力できること、GPUメモリー不足で共通停止すること、失敗した新しいテンプレート作業から古い作業を誤分割しないことを回帰試験に含めています。

移動検証と配布物のハッシュ等は、候補に添える最終検証結果報告を参照してください。全資産を新しくオンライン取得する試験とは区別しています。

## 残る受入確認

- DocuWorks 9.1実機での作成・矩形保存・再読込み・抽出。
- Viewerでの手動表示、不要矩形削除、追加、移動、拡縮、保存、再分割。修復警告と位置を確認。
- 現地の日本語実務図面で長い値、空欄、罫線、複数行、版違いを評価。
- 別PCでPython未導入状態から構築し、対応GPU/DocuWorksとフォントを確認。

## 受入の操作

1. 見本とは別の値を持つ図面を用意し、正解を人が記録する。
2. 見本から作成したXDWをViewerで編集し、分割後にファイル名を項目名へ変更する。
3. 別図面を抽出し、Excel値・切り出し画像・元ページ位置・状態・理由を照合する。
4. Excelを訂正した後に再出力し、訂正済みファイルが変わらないことを確認する。
5. アプリ全体を改名・別ドライブへコピーし、旧パスを参照しない状態で同じ操作を確認する。

画像XDWの背景はラスタライズによる微小差があるため、元PNGとの画素単位の完全一致を要求しません。実寸、基準位置、値欄を正しく切り出せることを確認します。

## v0.1.1 パス短縮

配置先をE:\ROI-OCRへ短縮し、起動時と初期設定で配置先40 UTF-16単位を検査します。内部ID・階層・一時名を短縮し、既存data/runsからのExcel再出力を維持します。

差分CPU試験119件が成功しました。40/41、240/241、補助文字、排他一時名、過長パスの事前拒否、旧形式の再出力を含みます。SDK一時名短縮後も実機で6矩形の作成・分割・画像化が成功し、SDK実パス最大は65単位でした。

固定91wheelの16,109エントリーと既存runtimeを実測し、最長相対パスは160単位です。移動後の21,463ファイルでも絶対パスの最大は171単位、新しい抽出結果内の最大は74単位でした。

E:\ROI-OCRで初期設定BATを別の作業フォルダーから実行し、終了コード0、GPU OCR・SDK矩形の読戻し成功を確認しました。BAT引数の処理前に配置先を保持する修正も含みます。構築済み環境・検証済みcacheの再利用であり、全取得物の新規ダウンロード試験ではありません。

通常の抽出BATで人工PDF/XDW計8ページを再処理し、48項目すべてが期待値と一致しました（取得40、未検出8、処理失敗0）。処理時間41.43秒、先頭ゼロ保持、Excel数式ノード0、入力SHA不変を確認しました。旧data/runsの8ページの保存結果からも新しいExcelを再出力でき、従来の保存結果・Excel等334ファイルとv0.1.0配布ZIPのSHAは不変でした。

最終配布物のハッシュと展開後試験は、候補に添える検証報告を参照してください。Viewer手編集・9.1・実務図面・別PCは引き続き未検証です。

## v0.1.2 確認済みマーカー

2026年10月15日、`確認済みマーカー.bat`を追加しました。「確認情報」シートの状態が「確認済み」の行を、抽出時の保存結果・根拠ID・座標と照合し、新しいXDWへ実黄色MARKERを付与します。Excel値の訂正をOCRへ取り込む処理、再OCR、原本や既存Excelへの書込みはありません。

- 自動試験205件成功。追加分にはExcel部品参照、共有文字列・inline・数値、並べ替え、重複行、数式・不正XML/ZIP拒否、保存結果・原本・cropのSHA検査、失敗時の一括取消しを含みます。
- 実BATの番号選択・Excelパス指定で、人工資料の確認済み10行からPDF/XDW各4ページ、計8ページを保持した2文書へ出力。対象10範囲（うち空欄2）に18個の黄色MARKERを配置し、保存後再読込みで設定・位置を照合。原本・既存Excel・保存結果・入力ExcelコピーはSHA不変でした。
- 2回目の実行も保存原本から新しい出力を作り、前回出力のSHAとマーカー数を保持。確認済み0行の場合は出力なし、終了コード1でした。
- 別の実機試料ではDocuWorks 10.1.1 / Core 1.0.1で、PDF/XDW各4方向（0/90/180/270度）、全8ページの黄色画素位置と既存注釈保持を確認。PDFの1ページだけを選んだ場合も全4ページを保持しました。元PDFの回転と画像XDWの出力回転0を別々に記録します。

これらは自作人工試料とSDK・画像化による検証です。GPU OCRは起動しておらず、Viewer手操作、9.1、現地実務図面、別PCの確認は引き続き残っています。v0.1.2はローカルの候補であり、公開済みv0.1.1のReleaseやタグを変更していません。
