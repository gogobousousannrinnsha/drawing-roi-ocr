# 図面範囲OCR v0.1.1

固定様式のPDF・XDWから、項目ごとに指定した範囲を切り出してOCRし、Excel一覧へ出力するWindows用アプリです。読み取った文字をそのまま出力し、結果は利用者が原本と照合します。

## 入手

[v0.1.1 Pre-release](https://github.com/gogobousousannrinnsha/drawing-roi-ocr/releases/tag/v0.1.1)の`roi-ocr-0.1.1-source.zip`を使用してください。ソース・同封Core・オンライン初期設定を含みます。初期設定でPythonとOCR資産を取得するため、構築済み環境の配布ではありません。SHA-256と内容一覧もReleaseへ添付しています。

ZIPの中身を`E:\ROI-OCR`等へ展開し、READMEと3つのBATがそのフォルダーの直下にある状態にしてください。アーカイブ名の長いフォルダーを重ねて作らないでください。確認済み・未確認の環境は下記の「検証と対応範囲」を参照してください。

## 保存先とパス長

推奨の保存先は E:\ROI-OCR です。アプリ配置先はWindowsの数え方で40文字以内とし、超える場合は開始前に停止して案内します。Windows全体の長いパス設定は変更しません。

内部の実行ID、保存階層、切り出し画像・SDK一時名を短くしています。新しい結果はdata/r、テンプレート作業はdata/wへ保存します。通常の生成パスは240文字、SDK実パスは255文字を上限に検査します。項目名・原本名の長さで超える場合は、使用者が分かる名前へ短くしてください。

以前のdata/runsやテンプレート作業、Excelは改名しません。既存の保存結果は再出力できます。

## 最初の準備

1. アプリ一式を書込み可能なフォルダーへ展開します。
2. `初期設定.bat`を実行します。公式配布元の固定版Python・OCR依存・モデルを取得して、アプリ内へ構築します。
3. `見本`、`input`、`templates`等のフォルダーが自動作成されます。JSONの手編集は不要です。

Windows x64、対応NVIDIA GPUとドライバー、正規に導入されたDocuWorksが必要です。CPUでの代替実行はありません。PDFを処理する場合も、XDWテンプレートの作成・読込みにはDocuWorksを使います。

固定構成はPython 3.13.15、PaddleOCR 3.7.0、PaddleX 3.7.2、GPU版Paddle 3.2.2、PP-OCRv6 medium検出・認識モデル、Core 1.0.1です。初期設定時の空き容量目安は約13.1GiBです。実際の必要量は起動時に取得済み資産から計算します。処理する図面と結果を保存する容量は別途必要です。

初期設定は通常のPythonやPATHを変更しません。実行環境、モデル、取得キャッシュはこのフォルダー内に置きます。取得中断後は同じフォルダーで再実行してください。DocuWorks本体・SDK DLL・NVIDIAドライバー・Windowsフォントは配布物に含めません。

## テンプレートを作る

1. `見本`直下に、見本のPDFまたはXDWを**1ファイル**置きます。
2. `テンプレート作成.bat`で「見本から編集用XDWを作成」を選びます。複数ページなら対象ページ番号を選びます。
3. 見本を300dpiで画像化し、全文OCR、白紙の`OCR確認.png`、矩形付きの`編集用.xdw`を作ります。画面に保存先を表示します。
4. `編集用.xdw`をViewerで開き、不要な矩形を削除します。残す矩形は、別の図面の値も収まる記入範囲へ広げます。空欄の項目には矩形を追加できます。
5. Viewerで保存し、文書を閉じます。もう一度`テンプレート作成.bat`を実行し、「編集後のXDWを項目別に分割」を選びます。
6. `templates/T_実行ID`に`項目_001.xdw`等が作られます。`Scale.xdw`や`Title.xdw`などへ改名します。様式フォルダー名も変更できます。

**1矩形＝1つのXDW、拡張子を除いたファイル名＝項目名、1フォルダー＝1様式**です。分割操作は直近に完成した編集用XDWを使います。以前の編集結果を分割する場合は、開発用コマンドの`--edited`でアプリ内の相対パスを指定できます。

テンプレートの背景は画像です。原本の文字や元注釈を編集するものではありません。元の見本は保持します。ページは切り詰めず、元の寸法を保ちます。赤い矩形は塗りなし、縦横3mm以上です。ラベルや隣接項目を含めず、値の範囲を指定してください。ページへ直接置いた長方形に対応し、グループや付箋内の矩形は使用できません。

## 通常の抽出

1. `input`直下へ同じ様式のPDF・XDWを置きます。サブフォルダーは検索しません。
2. `抽出.bat`で「inputから新規抽出」を選びます。様式が複数あれば番号を選びます。
3. 全ページに同じテンプレートを適用し、`exports/実行ID/抽出結果.xlsx`へ出力します。

通常抽出では全文OCRを実行しません。ページ画像を一度用意し、項目ごとの切り出し画像だけをOCRへ渡します。1実行でOCRエンジンを共用します。実行間のOCRキャッシュはなく、再実行では新しい結果を作ります。

ページ寸法・向きの許容差は幅・高さとも0.1mmです。不一致ページは理由付きで対象外にします。同じ用紙寸法でも欄の位置が違う図面は検出できないため、位置がそろった固定様式で使用してください。自動位置補正、図面のScale値による座標変更は行いません。

## Excelと保存結果

- **抽出結果**：1ページ＝1行。原本ファイル・ページ・各項目を並べます。項目列はファイル名順です。
- **確認情報**：取得・未確認、未検出、処理失敗、対象外を区別し、原文、信頼度、座標、切り出し画像の相対パスを記録します。

複数の認識領域は、上から下・同じ行は左から右へ並べ、改行で区切ります。元の文字列の空白や記号を変更しません。先頭ゼロや数式のような文字列も、文字として出力します。文字が見つからなくても「原本が空欄」とは断定しません。

`data/r/実行ID`には原本コピー、実際に使ったテンプレート、ページ画像、切り出し画像、OCR原文配列、局所・元ページ座標、Raw結果、処理条件を保存します。後からテンプレートを変えても過去の実行結果は保持します。

Excelの訂正はExcel内で完結します。保存済みOCRやテンプレートへ戻しません。正規化は本番側の別工程です。`抽出.bat`の「保存結果からExcelを再出力」はOCRを再実行せず、新しいExcelを作ります。修正済みExcelを上書きせず、以前のExcel訂正も引き継ぎません。Excel出力だけが失敗した場合も、完成済みOCRは再出力に使えます。

## 移動と失敗時の扱い

アプリ終了後にフォルダー全体をコピー・改名してください。一部だけを移すと再出力に必要な保存物が欠けます。移動先PCにも対応GPUとDocuWorksが必要です。長すぎる配置先ではSDKの一時パス制限により失敗することがあります。浅いフォルダーへ配置してください。

項目単位の認識失敗は理由を残して処理を続けます。モデル初期化、GPUメモリー不足、保存先など共通の異常では停止します。詳細は`logs`に残ります。成功0、一部失敗2、全体エラー1、中断130を終了コードとして返します。中断時に完了した保存物は保持しますが、未完了runからのExcel再出力はしません。

## 検証と対応範囲

実装と検証結果は`docs/verification.md`に記録します。DocuWorks 10.1.1で先行検証し、9.1も対応確認の対象とします。**9.1実機、Viewerでの手編集、実務図面、別PCで確認するまでは、それぞれを検証済みとは扱いません。** 人工資料や公開サンプルでの成功は、実務図面の認識精度を保証するものではありません。

初版にはLLM、様式の自動判定、画像ファイルの直接入力、Excel訂正の取込みを含めません。基準ソースは既存v0.1.5で、必要な画像化・OCR・白紙PNG・取得検査だけを再利用しています。

## 開発・自動実行

`source/run.py`には`template-create`、`template-split`、`extract-run`、`export`、`selfcheck`の非対話コマンドもあります。`--root`でアプリフォルダー、`--template`、`--edited`、`--run`ではアプリ内の相対パスを指定します。利用者向けBATは末尾へ`--no-pause`を付けると終了待ちを省略できます。

CPU試験はアプリのフォルダーで`python -B -m pytest`を実行します。ソースZIPは`scripts/build_source_zip.py --root APP --output ZIP`で作成します。配布対象にはソース・固定Core・初期設定処理・ライセンスだけを含め、入力、保存結果、runtime、モデル、ログは除外します。

構築済みの検証候補には、自作の人工見本・入力・テンプレートと試験出力を置いています。実務で使うときは、人工資料を別の場所へ保管して、使用する見本・入力・テンプレートへ差し替えてください。配布ソースZIPにはこれらの人工資料を含めません。
